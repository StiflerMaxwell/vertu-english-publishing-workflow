# VERTU 英文内容创作与交付 SOP

更新：2026-09-28。面向接手选题、资料整理和英文创作的同事。

## 第一天从这里开始

1. 先阅读本公开仓库；当前产品知识库与已批准选题由负责人通过授权渠道提供。没有权限时请负责人提供有日期和版本的授权资料，不自行寻找生产 token。
2. 阅读 [当前配置](CURRENT-OPERATING-PROFILE.md)：每日生产目标 5 篇，质量优先；这是团队总量，不是每个作者各发 5 篇。补发也计入当天数量。
3. 阅读 [写作标准](../skills/vertu-english-blog-pipeline/references/writing-contract.md) 和 [产品事实标准](../skills/vertu-english-blog-pipeline/references/product-knowledge.md)。
4. 复制 [单篇交稿模板](../templates/creator-submission.md)，先完成一篇供独立编辑审阅，不直接批量生成五篇。
5. 只负责创作的同事不必先安装全部自动化，也不需要 CMS 写权限。需要用 AI 工具时，将本 SOP、上述标准、已通过的选题 brief 和授权证据一起提供；不得要求工具跳过门禁。

## 谁负责哪一步

| 角色 | 负责 | 不得自行做 |
|---|---|---|
| 选题负责人/已配置的选题执行器 | 当前需求数据、查重、品牌相关性、计算评分、SERP 差异化 | 凭印象给最终分数、把热点标签当证据 |
| 内容创作者 | 查证、论点、正文、SEO、逐条声明依据、配图需求 | 编造体验/参数、把未验证推断写成事实、直接发布 |
| 独立编辑与 QA | 实质审稿、事实与重复检查、正式 QA 与精确版本交接 | 作者自评代替独立审核、沿用旧稿的 PASS |
| 授权发布人 | 当前 schema/revision、预览、CMS 操作、线上回读、台账 | 将 API 成功当成上线验收、盲目重试不确定写入 |
| 监测负责人 | 24h/72h/7d/28d 检查、成熟数据复盘 | 数据缺失写成零、未经授权改线上文章 |

## 完整流程与每步交付

| 步骤 | 做什么 | 交付/验收 |
|---|---|---|
| 1. 选题 | 明确一个真实读者问题、需求证据和站内查重；生产选题走品牌门禁、确定性评分与独立需求来源 | topic-brief.md、选题证据；自动生产需计算分数≥80且所有资格门禁通过 |
| 2. 差异化 | 对准确关键词、地区、语言做 SERP 基准；说明比已有文章多解决什么 | serp-benchmark.json、ranking-page-anatomy.json、content-differentiation-brief.md；只有 PASS 才进入生产写作 |
| 3. 查证 | 收集官方一手信息；标注发布时间与事件时间；涉及 VERTU 时读当前知识库并核对实时商品信息 | evidence-pack.md、product-context.json；缺资料记 UNKNOWN，不编造 |
| 4. 大纲 | 一个问题、一句结论、分节证据、一个具体增量价值 | outline.md；不是可以随意调换的小标题拼盘 |
| 5. 正文 | 英式英语，开头回答问题，交代适用与不适用人群、代价和限制 | article.md、seo.json、claim-ledger.json、link-plan.json |
| 6. 编辑 | 检查论证、冗余、模板味、品牌硬插与事实限定；五篇之间不得只是换实体 | quality-review.md（READY/REVISE/REJECT）、editorial-changes.md |
| 7. 独立 QA | 对精确文件版本检查事实、意图、SEO、风险；生产包记录指纹、政策哈希和 QA Run ID | qa-report.md、qa-handoff-preflight.json；FIX 返修，BLOCK 停止 |
| 8. Discover 与图片 | 核对标题预览、内容增量、时效和视觉；官方素材也要确认来源及使用权限 | discover-readiness.json、image-brief.md、visual-verification.json |
| 9. 授权发布 | 发布人读取实时 schema、预览与精确 revision，进行发布前 QA 后才写入 | prepublish / postpublish handoff；新人交稿不执行此步 |
| 10. 上线验收 | 检查真实页面，不能只看 CMS | HTTP、canonical、正文、唯一链接作者/schema、图片、内外链、桌面/手机展示、Base 回读 |
| 11. 复盘 | 24h 技术与初步互动；成熟72h流量；7d优化；28d长期学习 | 有真实观测和明确缺失状态的监测记录 |

完整机器契约见 [生产 Skill](../skills/vertu-english-blog-pipeline/SKILL.md)、[QA Skill](../skills/vertu-seo-publish-gate/SKILL.md)、[QA 交接](../contracts/VERTU-QA-Handoff-Contract.md) 和 [运营手册](OPERATIONS.md)。本 SOP 不替代机器契约。

## 每篇必须达到的内容要求

- 不是“整理了哪些信息”，而是“帮助读者做什么决定”。比较稿要写选谁、为什么、什么情况下不要选。
- 至少一个有内容的对比表、决策矩阵、可执行清单、计算或时间线；它必须对应本篇问题，不能每篇复制同一模板。
- 字数服务于问题深度，不靠凑字数通过。FAQ 只有真实需求才加。
- 产品型号、价格币种、地区、材料、续航、发布日期、服务权限逐项有来源。续航要写使用模式，不能混用待机与持续使用。
- 材料耐刮不等于抗冲击；硬件隔离不等于绝对隐私；型号之间不能借用功能；不要写未经验证的“终身”“绝对”“保证”。
- 来源链接应出现在读者能看到的正文，不只藏在研究文件里。实时商品事实与内部知识库冲突时上报，不静默挑一个。
- VERTU 只在与论点有关时出现，最多一个解释性品牌/礼宾整合段。不要把编辑文章改成一长段广告。
- 不虚构个人试用、测评、专家资历或用户评价；不要根据检测器分数判断质量。
- 自动编辑内容只用 guides / ai-tools / lifestyle；news 不属于普通创作者的自动发布路径。

## 交稿目录

```text
article-slug/
  submission.md               # 从模板填写：负责人、稿件版本、阻塞和请求
  topic-brief.md
  evidence-pack.md
  product-context.json        # 无产品时说明不适用
  outline.md
  article.md
  seo.json
  claim-ledger.json
  link-plan.json
  image-brief.md
  quality-review.md           # 独立编辑填写；作者不得代签 READY
```

生产所需评分、SERP、指纹、QA 和发布验收文件由相应执行器补齐。作者的“自检完成”不等于生产包已经合格。稿件与业务资料应通过负责人指定的私有渠道交付，不将正文、分析导出或客户资料直接提交到流程仓库。

## 提交前自检

- [ ] 标题、第一段、表格和结论指向同一个问题。
- [ ] 每个数字、功能、价格和服务承诺都有对应型号与原始来源。
- [ ] 不同产品名称与特性没有错位，金额符号和表格未丢失。
- [ ] 未确认项不在可发布正文里，保留在声明表中待处理。
- [ ] 链接、日期、图片和 alt 与本篇内容一致；没有工具占位符或内部提示词。
- [ ] 写出比较限制、不适用情况和证据边界。
- [ ] 已说明本篇增量价值，与最近文章没有重复意图。
- [ ] 已交给独立编辑；未自行声称 QA PASS 或上线成功。

## 遇到问题怎么停

知识库或研究源不可用：保留已完成工作，列出缺哪条证据及负责人；不得把旧资料标成当前。
SERP 不可用：不得编造排名或地区结果，也不能绕过生产选题门禁。
规格冲突：暂停相关结论，请产品负责人确认；不要用更好看的参数。
QA 返修：只修改指出问题并核对所有受影响段落，产生新版本供重审。
图片不合格：请求授权真实素材，不能生成虚构产品图。
发布状态不确定：交给发布人核对事务和当前 revision，不连续点发布。

## 交接完成的判据

接手人能独立提交一篇“论点清晰、证据可追溯、元数据和图像需求齐全”的稿件，独立编辑能据此审核，发布人能明确看到哪些门禁已完成、哪些未完成。GitHub 可访问不等于生产权限已开通。
